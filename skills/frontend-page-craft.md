# 前端页面工程：需求分析 → 设计 → 实现 → 验收

这是一个**执行层**技能：不写泛泛的设计原则，只给判断、顺序、模板和门禁。
适用：新页面、重做页面、后台/仪表盘/落地页/H5/数据大屏/文档站/AI 对话产品、选组件库、建设计系统。

**默认产物**（除非用户只要一段代码）：

```
BRIEF.md      需求分析与验收标准（阶段 A）
DESIGN.md     视觉方向、令牌、布局与组件映射（阶段 B）
src/…         实现（阶段 C）
VERIFY.md     验收记录：逐项勾选 + 证据（阶段 D）
```

只做单文件 demo 时，把 BRIEF 与 DESIGN 压成回复里的两小段，仍必须给出四态与验收结论。

## 1. 第一步：判页面类型，再开资源

类型决定骨架、密度、组件库和验收重点。一次只选一个主类型；混合型按主用途选。

| 类型 | 信号 | 骨架与密度 | 必读资源 |
| --- | --- | --- | --- |
| 后台 / 管理台 | 列表、筛选、增删改、权限 | 侧栏 + 顶栏 + 内容区；紧凑 8px 密度 | `page-archetypes.md`（后台管理节）、`stack-decisions.md`（PC UI 节） |
| 仪表盘 / 看板 | 指标卡、趋势图、多图组合 | 12 栅格卡片流；先概览后下钻 | `page-archetypes.md`（仪表盘节）、`component-catalog.md`（可视化节） |
| 营销 / 落地页 | 转化目标、首屏主张、信任状 | 单列叙事 + 证据区；大留白 | `page-archetypes.md`（落地页节）、`design-direction.md` |
| 移动 H5 / 小程序 | 触控、单手、弱网 | 390px 基准、底部操作区、44px 触控 | `page-archetypes.md`（移动端节）、`stack-decisions.md`（移动 UI 节） |
| 数据大屏 | 16:9、远距离、实时 | 缩放适配 + 绝对定位分区 | `page-archetypes.md`（数据大屏节）、`component-catalog.md`（大屏节） |
| 文档 / 内容站 | 长文、目录、检索 | 侧目录 + 正文 65–75 字符宽 | `page-archetypes.md`（文档站节） |
| AI 对话产品 | 流式输出、多轮、工具调用 | 消息流 + 输入区 + 侧栏会话 | `page-archetypes.md`（AI 对话节） |

**路由规则**：先读本文件 → 按上表读 1 个范式 + 1 个选型文件 → 需要落地细节再读实现手册/验收清单。
不要一次性把所有资源读进来；资源是「按阶段取用」的。

## 2. 阶段 A：需求分析（Brief）

目标：把「做个页面」变成**可验收的约束**。这一步做完才允许写代码。

### 2.1 必须拿到的信息（拿不到就假设并写明）

| 维度 | 必须回答 | 缺失时怎么办 |
| --- | --- | --- |
| 用户与场景 | 谁在什么设备、什么网络、什么频率用 | 按主类型给最常见画像，写进 BRIEF「假设」 |
| 业务目标 | 这个页面促成的**一个**动作 | 假设为「完成主任务」，并标注待确认 |
| 真实内容 | 标题、字段、示例数据从哪来 | 用**真实语义占位**（真实字段名、真实量级），禁止 Lorem/foo |
| 技术约束 | 框架、组件库、浏览器、是否允许装依赖 | 默认 Vue3+TS；**装依赖前必须问** |
| 品牌约束 | 有无 VI/色值/字体/禁用元素 | 无则用 `design-direction.md` 的方向配方 |
| 交付形态 | 单页 demo / 可运行项目 / 组件 | 决定产物与验收深度 |

### 2.2 提问规则（省 context，也不打断）

1. 一次最多 3 个问题，且**只有阻塞性**的才问：无数据来源、无技术栈、无品牌但用户明确要「像某品牌」。
2. 能在文件/仓库里查到的，先查；能从主类型推断的，写进「假设」并继续。
3. 不复述需求、不问「你想要什么颜色/风格」——这类由你按方向配方决定并给理由。

### 2.3 BRIEF.md 模板（直接抄）

```markdown
# BRIEF — <页面名>

## 1. 一句话目标
<谁> 在 <场景> 完成 <一个动作>，成功标志是 <可观测结果>。

## 2. 用户与设备
- 主用户：…（角色/熟练度）
- 设备与视口：桌面 1440 / 平板 768 / 手机 390（保留需要的）
- 网络与频次：…

## 3. 页面内容清单（真实语义）
| 区块 | 作用 | 必备元素 | 数据来源 |
| --- | --- | --- | --- |
| 首屏 | 主张 + 主 CTA | H1、副标题、按钮 | 文案 |
| 数据区 | … | … | API `/api/x` / mock |

## 4. 状态清单（全部要实现）
- loading / empty / error / 部分失败 / 无权限 / 超长文本 / 0 条 / 1 条 / 1000 条

## 5. 约束与假设
- 技术栈：…（版本以项目为准，不硬编）
- 品牌：…（无则写「用 design-direction 方向 X」）
- 假设：…（每条标注「待确认」）

## 6. 验收标准（可测，不用形容词）
- [ ] 390/768/1440 三档无横向滚动，首屏主信息在首屏内
- [ ] 键盘 Tab 可完成主流程，焦点环可见
- [ ] 文本对比度 ≥ 4.5:1，大字 ≥ 3:1
- [ ] 空/错/慢三态有明确界面，不是白屏或转圈
- [ ] 首屏 JS（gzip）≤ 200KB；LCP ≤ 2.5s（3G Fast 模拟）
```

**门禁 A**：BRIEF 的验收标准里出现「好看、现代、大气、高级」这类不可测词 → 改写为结构/对比度/密度/时延等可测项，否则不进入设计。

## 3. 阶段 B：设计（DESIGN.md）

先定「方向」，再定「令牌」，最后定「组件」。顺序不能反——先挑组件会得到拼贴感。

### 3.1 选一个视觉方向（4 选 1，禁止混搭）

| 方向 | 气质 | 适合 | 令牌配方 |
| --- | --- | --- | --- |
| A 克制专业 | 中性灰底、单一强调色、少阴影 | 后台、B 端工具、文档 | 中性 9 阶 + 1 强调色；圆角 6–8；阴影极轻 |
| B 编辑杂志 | 大字号衬线/窄体、强对比、分栏 | 内容站、品牌、作品集 | 字号跳档 1.5×；黑白+1 品牌色；无卡片阴影 |
| C 产品化 SaaS | 明亮、圆角 10–14、柔和阴影、渐变点缀 | 落地页、SaaS 官网、AI 产品 | 蓝/靛主色 + 中性灰；柔和投影；2 个强调色上限 |
| D 实验未来 | 深色、发光、网格/噪点、WebGL | 大屏、活动页、3D 展示 | 深底 + 高饱和单色发光；等宽字体点缀 |

详细色板、字号阶梯、间距与动效曲线见 `design-direction.md`；选型依据见 `stack-decisions.md`。

### 3.2 设计令牌（写进 DESIGN.md，代码里只引用变量）

```
色：--bg / --surface / --border / --text / --text-muted / --accent / --accent-contrast / --danger / --warning / --success
字：--font-sans / --font-mono；字号 12/14/16/20/24/32/40/56；行高 1.5 正文、1.2 标题
距：4 的倍数；页面边距 16/24/40；卡片内边距 16/24
形：圆角 4/8/12/999；边框 1px；阴影 0 1px 2px / 0 8px 24px 两级
动：120ms 微交互、200ms 过渡、320ms 入场；曲线 cubic-bezier(.2,.8,.2,1)；尊重 prefers-reduced-motion
```

规则：**一个页面最多 1 个强调色 + 1 个语义色族**；同类元素只有一个尺寸；禁止每个卡片不同圆角/阴影。

### 3.3 布局骨架

- 先画「区块顺序」再画细节：首屏 → 主内容 → 证据/明细 → 行动区。
- 桌面用 12 栅格（最大内容宽 1200–1280，阅读宽 65–75 字符）；移动单列，断点 640 / 900 / 1200。
- 密度二选一并贯彻：舒适（行高 1.6、区块间距 48–96）或紧凑（行高 1.4、区块间距 24–32）。B 端默认紧凑，营销默认舒适。
- 视觉层级只靠三件事：字号、字重、留白。不要靠彩色边框堆层级。

### 3.4 组件映射（必须查表，不许凭记忆）

1. 打开 `component-catalog.md`，按「类型 → 生态 → 状态」筛选，只选 `active` 的库；`legacy/stale` 仅用于维护旧项目。
2. 用 `stack-decisions.md` 的默认项，除非项目已有既定栈（已有栈优先，别引入第二套 UI 库）。
3. 写出**组件映射表**：页面区块 → 库组件名（用真实存在的组件名）→ 需要自研的部分。
4. 组件库覆盖不到的（空状态插图、复杂筛选器、图表容器）明确写「自研」，不要硬套。

### 3.5 DESIGN.md 模板

```markdown
# DESIGN — <页面名>
## 方向
方向 B（编辑杂志）· 密度：舒适 · 强调色：#C2410C

## 令牌
（贴 CSS 变量块）

## 布局
（ASCII 线框：区域 + 栅格 + 断点行为）

## 组件映射
| 区块 | 组件 | 来源 | 自研? |
| --- | --- | --- | --- |

## 图表/大屏专项
图表库：ECharts 5（按需引入）· 图表数：3 · 缩放方案：v-scale-screen
## 不做清单
（明确不做的功能，防止范围膨胀）
```

## 4. 阶段 C：实现

### 4.1 依赖与脚手架（硬规则）

- **先问再装**：任何 `npm i` / `pnpm add` 之前，确认框架、包管理器、是否允许新增依赖。已有项目沿用既有栈。
- 单页 demo 优先零依赖（原生 HTML/CSS/JS 或项目已装库），能不发请求就不发。
- 图库按需引入（ECharts `echarts/core` + 需要的 chart/component），禁止整包。
- 版本号不写死在新代码注释里；以项目 lockfile 为准。

### 4.2 实现顺序（每步可运行）

1. 骨架与令牌：布局容器 + CSS 变量 + 断点。
2. 静态内容：真实语义文案与数据结构，先不做交互。
3. 状态四件套：loading / empty / error / 边界（超长、0 条、无权限）。
4. 交互：主流程 → 次要动作 → 键盘与焦点。
5. 响应式三档复核。
6. 动效：只加有信息价值的（入场、状态切换、图表更新），统一时长与曲线。
7. 清理：删调试代码、无用依赖、占位假数据（或标注 mock）。

代码骨架（Vue3 与 React 双版本）、请求层、表单/表格/图表封装见 `implementation-playbook.md`。

### 4.3 质量预算（写进验收）

| 项 | 目标 |
| --- | --- |
| LCP | ≤ 2.5s（中端移动 + Fast 3G 模拟） |
| CLS | ≤ 0.1（图片/图表预留尺寸） |
| 首屏 JS | ≤ 200KB gzip（图表另计，按路由懒加载） |
| 触控目标 | ≥ 44×44px |
| 对比度 | 正文 ≥ 4.5:1；大字 ≥ 3:1；禁用态另算但需可辨 |
| 焦点 | 所有可交互元素 `:focus-visible` 可见，顺序符合阅读序 |
| 动效 | 尊重 `prefers-reduced-motion`；不阻塞输入 |

### 4.4 安全红线

- 禁止 `eval` / `new Function`；`v-html`、`dangerouslySetInnerHTML` 必须消毒（DOMPurify 或后端白名单）。
- 外链 `target="_blank"` 必须带 `rel="noopener noreferrer"`。
- 不在前端硬编码密钥；接口错误信息不回显堆栈。
- 用户输入进入 URL/查询参数前编码；文件名/路径做白名单。

### 4.5 规范自检（写完代码先跑，别等验收）

零依赖检查器覆盖 32 条红线（安全 / 可访问性 / Vue 模板 / TS / HTML / CSS / 性能），
每条都标了出处（ESLint、Airbnb、Google、Vue 风格指南、WCAG 2.2、OWASP、web.dev）：

```bash
node <资源目录>/bin/check-standards.mjs --path . --fail-on p1
```

- 支持目录或单文件；`.vue/.svelte/.astro/.html/.ts/.tsx/.css` 等；
- P0 是安全/可访问性阻断（XSS、`target=_blank` 无 rel、`img` 无 alt、去 outline、`v-for` 无 key 等）→ 必须修。
- P1 是规范债 → 本次交付内修掉；确实无法修时在 VERIFY.md 写明原因与计划。
- P2 是卫生项 → 记录待办，不阻塞。
- `--list-rules` 查规则 id；`--ignore 规则id` 或项目根 `.standardsignore` 单条豁免。
- 规则细节、依据链接与已知限制见 `standards.md`。

它不替代 ESLint：ESLint 管语法与类型，这个检查器管**模板组合、跨文件 id、密钥、内联资源**这些 ESLint 默认看不到的红线。

### 4.6 反 AI 味（硬清单，逐条自检）

1. 默认紫蓝渐变 + 三张等宽卡片 + 圆角发光按钮 → 重写，按方向配方。
2. emoji 当图标 → 用图标库或纯 CSS 几何图形。
3. 每段都居中、每个区块都是卡片 → 至少一个区块用分栏或表格承载信息。
4. 假数据（Lorem、user1@example.com、数字 12345）→ 换成真实语义与真实量级。
5. 标题与正文只差 2px、字重一样 → 层级跳档 ≥ 1.25×。
6. 卡片阴影五颜六色、圆角各不相同 → 统一两级阴影与一套圆角。
7. 所有按钮同权重 → 主次明确，一屏只有一个主 CTA。
8. 只做 happy path → 必须给空/错/慢/超长。
9. 图标与文字语义不一致（放大镜表示设置）→ 语义对齐。
10. 深色模式靠反色糊过去 → 深色是独立配方（对比度、阴影、图表色）。
11. 首屏堆三个功能模块却没有一句人话主张 → 首屏先讲清「这是什么、给谁、下一步做什么」。
12. 表格缺对齐与数字右对齐、表头不吸顶 → 数字右对齐、等宽、表头 sticky。
13. 图表无标题/单位/图例解释，颜色仅靠色相区分 → 加单位、图例、形状/纹理辅助。
14. 动效满屏飞入、每次滚动都触发 → 最多两处入场，其余克制。
15. 复制粘贴的「Hero + Features + Pricing + FAQ」套版却没有内容 → 宁可少区块，也要有信息量。

> 以上任一条不满足，视为未完成，回到阶段 B 改设计，而不是在代码里打补丁。

## 5. 阶段 D：验收

0. **先跑规范检查**：`node <资源目录>/bin/check-standards.mjs --path . --fail-on p1`；有 P0/P1 先修，不进入人工验收。
1. 按 `qa-checklist.md` 逐项勾选（P0 必须全过；P1 记录为待办）。
2. 能截图/开浏览器时：三档视口各截一张，检查溢出、遮挡、断行、焦点与四态；对比度用取色器抽检 3 处。
3. 不能开浏览器时：明确写「视觉未验证」，只报静态检查结论，不冒充已验证。
4. 输出 `VERIFY.md`：通过项、失败项、证据（截图路径/命令输出）、遗留风险。
5. 修复循环：一次只改一类问题，改完重跑对应项，避免「改样式改坏交互」。

**门禁 D**：P0 项有任一未过 → 不宣称完成；用「已完成 + 未验证项」的措辞交付。

## 7. 常见失败 → 处方

| 症状 | 处方 |
| --- | --- |
| 页面「能用但廉价」 | 回阶段 B：定方向 + 令牌；补齐层级（字号/字重/留白）与一个真实证据区 |
| 组件风格打架 | 只留一套 UI 库；自研组件对齐令牌，不引入第二套圆角/阴影 |
| 首屏慢 | 图表/编辑器/3D 全部懒加载；首屏只留骨架与关键 CSS |
| 移动端错位 | 390 基准重排，去掉固定宽，触控 ≥44，避免 hover-only 交互 |
| 大屏在 2K/4K 糊或溢 | 用缩放方案（v-scale-screen 或 transform: scale）统一 16:9 画布 |
| 用户说「不是我想要的」 | 拿 BRIEF 的验收标准对照，找**错的是目标还是执行**，先改目标再改像素 |
